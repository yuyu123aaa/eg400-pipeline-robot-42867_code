# 管道缺陷图像采集与 LabelImg 标注说明

## 1. 任务目标

本次任务只包括：

1. 使用项目实际摄像头采集管道缺陷图片；
2. 筛选并删除重复、模糊或无法辨认的图片；
3. 使用 LabelImg 对缺陷进行矩形框标注；
4. 将图片、YOLO 标签和类别文件整理后交付。

不需要训练 YOLO 模型。

## 2. 数据量目标

本次采用以下采集目标：

| 类别编号 | 英文标签 | 中文名称 | 有效图片目标 |
| ---: | --- | --- | ---: |
| 0 | `root` | 树根侵入 | 300 张 |
| 1 | `hole` | 破洞 | 300 张 |
| 2 | `crack` | 裂缝 | 300 张 |
| 3 | `spalling` | 管壁脱落 | 300 张 |
| 4 | `sediment` | 泥沙淤积 | 300 张 |

另外采集 150～200 张无缺陷管道图片，用于减少模型把阴影、污渍和反光误判成缺陷。

预计最终数据量：

- 缺陷图片约 1500 张；
- 无缺陷图片约 150～200 张；
- 总计约 1650～1700 张。

这里的 300 张指经过筛选的有效图片，不是从同一段视频连续截取的 300 个相似画面。

## 3. 固定类别顺序

LabelImg 必须始终使用以下类别名称和顺序：

```text
root
hole
crack
spalling
sediment
```

对应的类别编号固定为：

```text
0 root
1 hole
2 crack
3 spalling
4 sediment
```

禁止事项：

- 不要中途调整类别顺序；
- 不要使用 `root1`、`holes`、`cracks` 等其他拼写；
- 不要在一部分数据中使用英文、另一部分数据中使用中文；
- 不要删除或修改 LabelImg 生成的 `classes.txt`。

可以提前创建 `predefined_classes.txt`：

```text
root
hole
crack
spalling
sediment
```

## 4. 图像采集设备

优先使用机器人实际部署时的设备和环境：

- 使用项目实际摄像头；
- 使用机器人实际补光灯；
- 尽量在与比赛演示接近的管道中拍摄；
- 保持摄像头分辨率和实际运行时一致；
- 推荐保存为 JPG 格式；
- 推荐分辨率为 640×480 或摄像头原始分辨率。

尽量不要将网上下载的图片作为主要训练数据，因为网上图片的拍摄角度、镜头、光照和实际机器人画面差异较大。

## 5. 每类图片的多样性要求

每类 300 张图片应尽量覆盖不同情况。

### 5.1 拍摄距离

- 近距离：缺陷占据画面较大区域；
- 中距离：缺陷大小接近比赛实际识别情况；
- 远距离：缺陷在画面中较小但仍能够辨认。

建议中距离图片最多，近距离和远距离图片作为补充。

### 5.2 缺陷位置

缺陷不能始终位于画面正中央，应覆盖：

- 画面中央；
- 左侧和右侧；
- 上方和下方；
- 靠近画面边缘；
- 部分超出画面。

### 5.3 拍摄角度

- 正面；
- 左右倾斜；
- 上下倾斜；
- 摄像头轻微旋转；
- 机器人靠近管壁或偏离管道中心。

### 5.4 光照情况

- 正常补光；
- 亮度稍低；
- 局部阴影；
- 局部反光；
- 管壁潮湿；
- 灯光距离变化。

不要为了增加数量而收集大量完全相同的画面。

## 6. 使用视频采集时的要求

可以先录制视频，再从视频中抽取图片。

建议：

- 每个摆放方式录制一段短视频；
- 每秒最多保留 1～2 张图片；
- 当摄像头角度和距离没有明显变化时，不要连续保留图片；
- 每一类至少设置 5～10 种不同摆放方式；
- 更换缺陷的位置、方向、背景、距离和灯光后再继续拍摄。

以下情况属于重复图片，应删除大部分，只保留其中少数代表性图片：

- 连续多帧中缺陷位置几乎不变；
- 缺陷大小、角度和光照完全相同；
- 只是时间不同，但画面内容基本一致。

## 7. 文件命名

文件名统一使用英文、数字和下划线，不使用中文、空格或特殊符号。

示例：

```text
root_0001.jpg
root_0002.jpg
hole_0001.jpg
crack_0001.jpg
spalling_0001.jpg
sediment_0001.jpg
normal_0001.jpg
```

每张图片必须使用唯一文件名，不能覆盖之前的数据。

如果由多次采集组成，可以加入批次编号：

```text
root_b01_0001.jpg
root_b02_0001.jpg
```

批次编号有助于后续将不同视频或不同场景分配到训练集、验证集和测试集。

## 8. 五类缺陷判断标准

### 8.1 `root`：树根侵入

判断特征：

- 能看到明显根须、纤维或树根结构；
- 通常呈分叉状、细丝状或成团结构；
- 树根从管道裂口、接口或孔隙进入。

标注规则：

- 一团相互连接的树根标一个框；
- 不需要给每一根细丝单独画框；
- 两团明显分离的树根分别画框。

### 8.2 `hole`：破洞

判断特征：

- 管壁出现明显洞口；
- 能看到黑色空洞或穿透区域；
- 管壁材料已经缺失并形成明显开口。

标注规则：

- 框住完整洞口及其边界；
- 不要只框洞口中心的黑色部分；
- 多个互不连接的洞口分别画框。

### 8.3 `crack`：裂缝

判断特征：

- 管壁上出现线状、分叉状或连续延伸的裂纹；
- 裂纹通常没有根须的纤维结构；
- 可能是横向、纵向、斜向或网状裂缝。

标注规则：

- 一条连续裂缝标一个框；
- 相互连接的分叉裂缝可以标成一个框；
- 相距较远、互不连接的裂缝分别画框；
- 长裂缝的框应覆盖完整可见长度。

### 8.4 `spalling`：管壁脱落

判断特征：

- 管壁表层起皮、剥落或材料脱落；
- 可以看到不规则的脱落边界；
- 没有形成明显穿透管壁的洞口。

标注规则：

- 框住完整脱落区域；
- 不要把周围正常管壁大面积框入；
- 多块明显分离的脱落区域分别画框。

与破洞的区别：

- 只有表层剥落，没有明显洞口：`spalling`；
- 已经出现明显穿透洞口：`hole`。

### 8.5 `sediment`：泥沙淤积

判断特征：

- 管道底部存在明显泥、沙、颗粒或沉积物堆积；
- 可以看到实际堆积范围、边界或颗粒纹理；
- 通常出现在管道底部，但也可能堆积在局部凹陷处。

标注规则：

- 框住实际可见的淤积区域；
- 不要把整条管道底部全部框入；
- 两处明显分离的淤积分别画框。

以下情况不要标成泥沙淤积：

- 普通水渍；
- 单纯阴影；
- 灯光反射；
- 没有明显堆积形态的轻微污迹。

## 9. 容易混淆的情况

| 画面特征 | 应标类别 |
| --- | --- |
| 黑色洞口、明显穿透区域 | `hole` |
| 表层起皮或剥落，没有洞口 | `spalling` |
| 细长暗线，没有纤维结构 | `crack` |
| 有根须、分叉或纤维结构 | `root` |
| 管底存在真实颗粒或泥沙堆积 | `sediment` |
| 只有阴影、水渍或反光 | 不标注 |

无法确定类别时不要猜测，将图片放入 `unsure` 文件夹，由其他队员统一复核。

## 10. LabelImg 标注步骤

1. 打开 LabelImg；
2. 点击 `Open Dir`，选择待标注图片目录；
3. 点击 `Change Save Dir`，选择标签保存目录；
4. 确认当前格式为 `YOLO`，不要使用 PascalVOC/XML；
5. 加载固定的 `predefined_classes.txt`；
6. 按 `W` 开始绘制矩形框；
7. 框住缺陷的完整可见区域；
8. 选择正确的英文类别；
9. 按 `Ctrl+S` 保存；
10. 切换下一张图片继续标注。

标注完成后，每张有缺陷的图片都应存在同名标签文件：

```text
root_0001.jpg
root_0001.txt
```

YOLO 标签文件内容类似：

```text
0 0.512500 0.463542 0.218750 0.302083
```

每行依次表示：

```text
类别编号 中心点X 中心点Y 宽度 高度
```

这些坐标已经由 LabelImg 归一化，不要手动修改。

## 11. 矩形框绘制标准

- 框应尽量贴近缺陷边缘；
- 框内不要包含过多正常管壁；
- 不要只框缺陷中心，要覆盖完整缺陷；
- 一个连续缺陷标一个框；
- 多个互不连接的缺陷分别画框；
- 同一张图片可以同时标注多个缺陷；
- 同一张图片可以包含不同类别；
- 缺陷部分超出画面时，只框住画面中可见的部分；
- 缺陷太小或太模糊、无法判断类别时不要勉强标注。

## 12. 无缺陷图片

无缺陷图片用于让模型学习正常管壁、阴影、接缝、污渍和反光，减少误报。

无缺陷图片中不绘制任何标注框，可以单独放入：

```text
negative_images/
```

无缺陷图片应覆盖：

- 正常管壁；
- 管道接口；
- 灯光反射；
- 普通阴影；
- 水渍；
- 轻微污迹；
- 摄像头运动造成的轻微模糊。

如果画面中确实存在五类缺陷之一，就不能作为无缺陷图片。

## 13. 图片筛选标准

应删除：

- 严重失焦；
- 大面积运动模糊；
- 画面过暗且无法辨认；
- 画面过曝且缺陷边界消失；
- 摄像头被完全遮挡；
- 与前后图片几乎完全相同；
- 无法确定真实类别。

可以适量保留：

- 轻微模糊；
- 弱光；
- 局部反光；
- 局部遮挡；
- 缺陷位于画面边缘。

适量困难样本有助于模型适应实际比赛环境，但不能让低质量图片占据大多数。

## 14. 标注质量检查

每完成约 100 张图片，进行一次检查：

- 是否始终使用 YOLO 格式；
- 类别名称和编号是否保持一致；
- 图片与标签文件名是否对应；
- 是否漏标明显缺陷；
- 是否存在类别选错；
- 矩形框是否过大或过小；
- 是否把阴影、反光、水渍误标成缺陷；
- 是否存在大量连续重复画面；
- `classes.txt` 顺序是否正确。

建议由另一名队员随机抽查每类至少 30 张标注图片。
