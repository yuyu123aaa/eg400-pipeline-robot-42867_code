# 系统概览一屏布局设计

## 目标

在桌面浏览器 100% 缩放下，让系统概览在 1920×1080 和 2560×1440 显示器上保持一致的信息结构，并在一屏内完整展示：

- 顶部统计卡片
- 姿态角与超声波数据
- 相机画面与 GIS 轨迹
- 完整设备控制面板

PID 参数调节和缺陷日志不在系统概览中显示，只在各自的侧边栏子页面显示。

## 页面结构

系统概览沿用现有区块和数据接口，不复制组件：

1. 统计卡片行
2. 传感器数据行
3. 相机与 GIS 双列工作区
4. 设备控制面板

`section-pid` 与 `section-logs` 仍保留在文档中，由现有 `switchView()` 负责在对应子页面显示。概览模式将明确隐藏这两个区块。

## 桌面布局

桌面端采用“固定内容自然高度 + 工作区占据剩余高度”的布局：

- 统计卡、传感器栏和控制面板使用其自然高度。
- 相机/GIS 行使用弹性高度，占据视口扣除其他区块后的剩余空间。
- 移除概览模式下相机/GIS 卡片的固定 `500px` 最小高度限制。
- 1920×1080 下优先保证全部控制按钮和存储路径完整出现。
- 2560×1440 下不放大按钮和文字，只让相机/GIS 工作区自然增高，保持视觉层级一致。

如果窗口高度不足、浏览器缩放增大或系统字体造成内容无法安全容纳，则恢复纵向滚动，不允许卡片重叠或裁切。

## 响应式行为

- 桌面端（宽度大于 1024px）：启用概览一屏布局。
- 平板和手机：继续使用现有纵向堆叠与滚动布局。
- 横屏触控设备：保留现有专用媒体查询，不强制套用桌面一屏高度。
- PID、缺陷日志、设备控制等专注子页面继续使用现有居中和隐藏规则。

## 代码改动范围

### `dashboard/app.js`

- 在 `switchView()` 中为内容容器设置当前视图状态类。
- `overview` 模式明确隐藏 PID 和缺陷日志。
- `pid`、`logs` 模式仍只显示各自区块。
- 页面切换后触发相机、GIS、3D 和 PID 图表尺寸刷新。

### `dashboard/style.css`

- 添加仅用于桌面概览的视口高度布局规则。
- 让中间工作区使用剩余高度，并允许内部图表正确缩放。
- 保持现有移动端、平板和横屏触控布局不变。

### `dashboard/index.html`

- 原则上不移动或复制区块；仅在需要稳定选择器时增加语义类名。

## 不在本次范围

- 不修改传感器数据采集。
- 不修改 PID 参数下发接口。
- 不修改设备控制接口。
- 不修改缺陷日志获取和渲染逻辑。
- 不改变相机流、GIS 或 3D 数据处理。
