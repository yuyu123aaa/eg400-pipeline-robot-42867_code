# YOLO 五分类英文画框设计

## 目标

实时视频中的 YOLO 检测框使用模型提供的五个英文类别名，显示英文严重程度，并为每个类别分配独立且固定的框颜色。解决中文标签通过 OpenCV Hershey 字体绘制时显示为问号，以及相同严重程度类别共用框色而难以区分的问题。

## 模型契约

部署模型的类别顺序固定为：

| 类别编号 | 模型名称 |
| ---: | --- |
| 0 | `spall` |
| 1 | `crack` |
| 2 | `hole` |
| 3 | `root` |
| 4 | `sediment` |

当前 `best.onnx` 的输入为 `[1, 3, 192, 256]`，输出为 `[1, 9, 1008]`。输出的 9 个通道由 4 个检测框参数和 5 个类别分数组成，现有 `pred[4:]` 后处理保持不变。

画框代码优先采用 ONNX 元数据中的类别名称。元数据缺失时，才按上述类别编号表回退；未知类别使用原始名称或编号安全显示。

## 显示规则

| 类别 | 英文严重程度 | OpenCV BGR 框色 | 视觉颜色 |
| --- | --- | --- | --- |
| `spall` | `Mild` | `(0, 255, 0)` | 绿色 |
| `crack` | `Moderate` | `(0, 255, 255)` | 黄色 |
| `hole` | `Severe` | `(0, 0, 255)` | 红色 |
| `root` | `Severe` | `(255, 0, 255)` | 紫色 |
| `sediment` | `Moderate` | `(255, 0, 0)` | 蓝色 |

五种颜色必须互不重复。检测框标签格式为：

```text
<class> | <severity> | <confidence>
```

例如：

```text
crack | Moderate | 0.87
```

标签全部由 ASCII 字符组成，继续使用 `cv2.FONT_HERSHEY_SIMPLEX`，不引入 Pillow、中文字体或额外的逐帧图像格式转换。

## 架构与数据流

`config.py` 保存只用于实时视频标注的英文类别显示配置，包括英文严重程度与类别框色。

`core/vision.py` 提供一个纯查询函数，根据模型类别编号和名称返回：

- 规范化后的英文类别名；
- 英文严重程度；
- 对应的 BGR 框色。

`_draw_scaled_yolo_result()` 使用该查询结果构造标签并绘制检测框。现有 `resolve_defect_profile()` 仍用于中文缺陷日志、CSV、处置建议和前端历史记录；本次不改变业务数据格式。

这样实时画框与业务严重度配置解耦：业务层仍可让 `hole` 和 `root` 同属重度，而画框层为它们提供不同颜色。

## 错误处理

- 模型名称使用去除首尾空格并转小写后的值进行匹配。
- 模型名称缺失时，根据类别编号回退到五分类顺序；模型提供了未知名称时不按编号替换，避免错误标注成已知类别。
- 未知 ASCII 名称保留原始值；未知非 ASCII 名称安全显示为 `class-<id>`，避免 OpenCV 再次绘制成问号。
- 未知类别的严重程度显示 `Pending`，框色使用灰色 `(128, 128, 128)`。
- 单个未知类别不得中断摄像头线程或影响其他检测框。

## 测试

- 验证五个类别均返回预期英文名称。
- 验证严重程度分别为 `Mild`、`Moderate` 或 `Severe`。
- 验证五个类别颜色两两不同。
- 验证缺失模型名称时按类别编号回退。
- 验证未知类别返回 `Pending` 和灰色。
- 验证最终标签不包含中文字符，且保留两位置信度。
- 运行现有完整测试集，确认中文日志、CSV、前端严重度和摄像头推流没有回归。

## 非目标

- 不修改 YOLO 推理、NMS、输入分辨率或置信度阈值。
- 不改变中文缺陷日志、CSV、处置建议和前端历史记录。
- 不重新训练或再次导出模型。
- 不引入中文字体渲染依赖。
